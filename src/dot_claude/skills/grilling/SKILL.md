# grilling

## 手法

共通理解に至るまで、ユーザーに質問し続ける。決定を **design tree** として捉える。どの決定にも、
それが決まって初めて決められる決定がぶら下がっている。

tree はラウンドごとに進める。**frontier** は、前提となる決定がすべて決まっている決定の
集まりで、まだ聞いていない答えを推測せずに今聞ける質問にあたる。1 ラウンドでは frontier の
質問をすべて出し、各問に推奨回答を付ける。次のラウンドに進む前に、ユーザーの回答を待つ。

ユーザーの回答を受けるたびに tree が変わる。決まった決定で frontier が外側へ広がり、それに
依存していた質問が聞けるようになる。frontier を計算し直して次のラウンドを出す。同じラウンドで
まだ答えの出ていない質問に依存する質問は、このラウンドではなく後のラウンドに回す。

**事実**を調べるのは自分の仕事で、ユーザーには聞かない。frontier の質問に環境(ファイル、
ツールなど)の事実が要るときは、新しいコンテキストで始まるサブエージェントに調べさせる。
調べられることをユーザーに聞かない。調査の完了を待って止まらない。調査中の事実は決まっていない
前提として扱い、それに依存する質問だけを待たせて、frontier の残りは今出す。**決定**はユーザーが
するもので、一つずつユーザーに示して回答を待つ。

frontier が空になったら終わる。design tree のすべての枝をたどり、黙って仮定したことが何も
残っていない状態である。ユーザーが共通理解に達したと確認するまで、決まった内容に着手しない。

## ラウンドの出し方

各ラウンドは browser-ask スキルのウィザードで出す。質問 JSON の書き方、推奨回答の示し方、
起動の手順は browser-ask に従う。grilling で加える点は次のとおり。

- ラウンドの質問を 1 問ずつ `questions` にし、`header` を「Q1 <題>」にする。
- 質問文は yes/no 形式にせず、推奨案と対案を選択肢として並べる。
- ラウンドごとに新しいウィザードを起動する。回答 JSON の `selected` と `other` を決まった
  決定として扱い、frontier を計算し直す。

ブラウザが使えない環境では AskUserQuestion で出す。AskUserQuestion は 1 回に 4 問まで、
選択肢は 4 件までなので、ラウンドの質問を 4 問ずつに分けて続けて出し、選択肢も 4 件に絞る。
ラウンドの全問に答えが揃ってから frontier を計算し直す。`header` は「Q1」のように短くする。
