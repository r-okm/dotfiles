# open-in-nvim - テキストファイルをユーザーに見せる

ユーザーはこの herdr のワークスペースに **nvim を常駐**させている（ふつうは 2 番目のタブ）。
読んでほしいファイルがあるとき、長いパスを応答に書いて手で開いてもらうのではなく、その nvim に
直接開く。ワークスペースに nvim がなく、2 番目のタブが shell に戻っているときは、スクリプトが
先に nvim を起動してから開く。

```bash
# ファイルを開く（バッファに開くだけ。ユーザーは自分で nvim のタブに移る）
~/.claude/r-okm/scripts/nvim-open.sh <path>

# 行（と桁）を指定して、そこにカーソルを置く
~/.claude/r-okm/scripts/nvim-open.sh <path>:<line>
~/.claude/r-okm/scripts/nvim-open.sh <path>:<line>:<col>

# 開いたうえで herdr の表示を nvim のタブに切り替える
~/.claude/r-okm/scripts/nvim-open.sh --switch <path>
```

1 回の実行で渡せるパスは **1 つだけ**。複数のファイルを開くときは、ファイルの数だけ実行する（下の「何を渡すか」）。他のフラグが必要になったら `~/.claude/r-okm/scripts/nvim-open.sh --help` を実行して確認する。

## 使うとき

- ファイルを「開いて」と言われたとき
- コードや設定の**特定の箇所**を「見せて」「どこ？」と聞かれたとき — 調べて行を突き止めたら、
  その行を開く。調べた結果を説明して終わりにしない
- 自分が見つけた行をユーザーに読んでほしいとき

## 例

| ユーザーの依頼 | 実行するコマンド |
| --- | --- |
| 「この設定ファイル開いて」 | `~/.claude/r-okm/scripts/nvim-open.sh src/config.ts` |
| 「エラーが出てる箇所を見せて」 | `~/.claude/r-okm/scripts/nvim-open.sh src/api.ts:142` |
| 「URL 判定してるとこどこ？」→ grep で 22 行目と判明 | `~/.claude/r-okm/scripts/nvim-open.sh script.sh:22` |
| 「書いたテストを見せて」 | `~/.claude/r-okm/scripts/nvim-open.sh tests/user_test.go` |
| 「今すぐ見たいから移動して」 | `~/.claude/r-okm/scripts/nvim-open.sh --switch src/config.ts` |
| 「このスクショ見せて」 | **使わない**（nvim はテキスト用） |
| 調査のために作った中間メモを読んだ | **実行しない**（中間生成物） |

## 何を渡すか

**ユーザーに読んでほしいファイル。** ふつうは話の中心にあるファイルを 1 つ選ぶ。触ったファイルを
全部開くことはしない。

ユーザーが複数のファイルを開くよう頼んだとき（スキルの引数に複数のパスが来たときも含む）や、説明が複数のファイルに
またがっていて、どれも読んでほしいときは、**全部開く**。1 つに絞って残りを「必要なら開きます」で済ませない。
スクリプトはパスを 1 つしか受け取らないので、ファイルごとに 1 回ずつ実行する。

```bash
~/.claude/r-okm/scripts/nvim-open.sh src/config.ts:12
~/.claude/r-okm/scripts/nvim-open.sh src/api.ts:142
```

前に開いたファイルは nvim のバッファに残り、画面には**最後に開いたファイル**が出る。いちばん先に読んでほしい
ファイルを最後に開く。nvim は 1 回目の実行で起動されるので、実行は 1 つずつ順に行い、並列にしない。

**箇所を特定できたなら必ず `:<line>` を付ける。** ユーザーが自分でジャンプ先を探さずに済む。
行番号やコードを応答に書くのは、開いたうえでの補足に留める。

## 開かないもの

- **自分が読むために作った中間生成物。** ユーザーが知りたいのは答えであって、Claude が答えを
  出すために作ったファイルではない。
- **画像・動画・バイナリ。** nvim はテキスト用。
- ユーザーが既に開いているもの、見る必要のないもの

「開かなくていい」と言われたら、単に開かない。それだけ。

## タイミングと切り替え

**応答を返す直前にまとめて開く。** 作業の途中で開かない。複数のファイルを開くときも、応答の直前にファイルの数だけ続けて実行する。
同じタスクで既に開いたファイルは、ターンが変わっても開き直さない。ユーザーが nvim で動かしたカーソルが戻されてしまう。

既定では **herdr の表示は切り替えない**。ユーザーは Claude の応答を読んでから自分で nvim の
タブに移る。`--switch` を付けるのは「すぐ見たい」「そっちに移して」と明示されたときだけ — 切り替えると
応答文が画面から消える。複数のファイルを開くときは、最後の 1 回だけに `--switch` を付ける。

## nvim が起動していないとき

ワークスペースに nvim がなく、2 番目のタブが shell のプロンプトで待機していれば、スクリプトが
そこに Claude の作業ディレクトリで nvim を起動してから開く。そうしたときは出力にその旨が出るので、応答で「nvim を起動して開いた」と
伝える。

## 失敗したとき

ワークスペースに nvim がなく、2 番目のタブが無いか、nvim でも shell でもないもの（Claude など）が
動いていると、このコマンドは **キーを送らず、何も開かずにエラーで終わる**。nvim が複数あって
2 番目のタブで 1 つに絞れないときも、何も開かずにエラーで終わる。タブやペインを作ったり動かしたりは
しない。その場合は
リトライせず（複数のファイルを開く途中なら残りも実行せず）、エラーの内容と応答にパスを書いてユーザーに伝える。
複数のファイルを開く途中で失敗したときは、開けたファイルと開けなかったファイルを応答に書き分ける。最後に開くはずだった
ファイルが開いていないので、画面には別のファイルが出ている。
