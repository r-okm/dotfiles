# open-in-explorer - 画像・動画をユーザーに見せる

Read tool で見た画像は**ユーザーのターミナルには表示されない**。長いパスを伝えて手で開いて
もらうのではなく、`explorer` コマンドで直接見せる。

```bash
# 単一の画像・動画を見せる（既定アプリが直接立ち上がる）
explorer --open <path>

# 複数の成果物から辿らせる（親フォルダが開き、そのファイルが選択される）
explorer <path>
```

上記 2 つで足りる。他のフラグが必要になったら `explorer --help` を実行して確認する。

## 例

| ユーザーの依頼 | 実行するコマンド |
| --- | --- |
| 「このスクショ見せて」 | `explorer --open shot.png` |
| 「このログをグラフにして」→ `chart.png` を生成 | `explorer --open chart.png` |
| 「構成図を書いて」→ `diagram.png` を生成 | `explorer --open diagram.png` |
| 「比較用に 3 パターン作って」→ 3 枚生成 | `explorer pattern_a.png`（代表 1 枚。残りは隣に見える） |
| 「この画像フォルダを開いて」 | `explorer <dir>` |
| 「この動画の内容を確認して」→ 読むためにフレーム抽出 | **実行しない**（中間生成物） |

## 何を渡すか

見せたい成果物の**代表となる 1 ファイル**。ファイルなら親フォルダが開いて選択状態になるので、
同じフォルダの残りも隣に見える。フォルダそのものが成果物のときだけディレクトリを渡す。

**ファイルの枚数では分岐しない。** 「複数あるから親ディレクトリ」にすると、中間生成物が同居して
いる場合に見せたいものが埋もれる。代表となる 1 ファイルを渡せば、残りはその隣にある。

**ユーザーが「見せて」と言ったときは、中間生成物ではなく元のファイルを開く。** ある動画について
話していたなら、そこから抽出した画像ではなく動画そのものを `--open` で開いて再生させる。

## 開かないもの

- **自分が読むために作った中間生成物。** ユーザーが知りたいのは答えであって、Claude が答えを
  出すために作ったファイルではない。抽出した画像、中間データ、デバッグ用の出力などが該当する。
- ユーザーが見る必要のないもの、ユーザーが既に開いているもの

「開かなくていい」と言われたら、単に開かない。それだけ。
