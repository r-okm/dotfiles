# セッション名の提案

この会話（セッション）のここまでの内容をもとに、セッション一覧で後から見分けやすい名前を提案する。材料は会話履歴とシステムプロンプトだけにする。

このスキルは名前を提案するだけで、セッション名を書き換えることはしない（`/rename` は Claude Code の組み込みコマンドで、モデルからは呼び出せない）。代わりに、推奨名を使った `/rename <推奨名>` の1行をクリップボードにコピーし、ユーザーが入力欄に貼るだけで実行できるようにする。

## クリップボードへのコピー

Bash ツールで次を実行する。`<推奨名>` を置き換える。

```bash
clipboard --yank <<'EOF'
/rename <推奨名>
EOF
```

## 手順

1. 会話全体を振り返り、次の3点を把握する。
   - 主目的：ユーザーが最終的に何を得ようとしていたか（最初の依頼ではなく、会話の中心になった作業）
   - 対象物：扱ったファイル名、システム名、顧客名、機能名などの固有の手がかり
   - 成果・状態：完了したのか、途中なのか、調査だけなのか
2. 主目的＋対象物を軸に、切り口の異なる候補を3つ作る。
   - 候補A：成果物・作業内容を表す（例：「請求書PDFの一括分割スクリプト」）
   - 候補B：対象システム・案件名を前に出す（例：「KSC勤怠システム API調査」）
   - 候補C：課題・目的を表す（例：「月次バッチ遅延の原因調査」）
3. 3つのうち、一覧で最も見分けやすいものを推奨として1つ選び、理由を一文で添える。
4. 推奨名で `/rename <推奨名>` の1行をクリップボードにコピーする（「クリップボードへのコピー」を参照）。

## 命名ルール

- 日本語で20字以内。超える場合は修飾語を削る。
- 「〜について」「〜の相談」「〜の件」などの中身のない語尾は使わない。
- 「雑談」「質問」「作業」のような一般語だけの名前にしない。固有名詞か具体的な動作を必ず含める。
- 会話の途中で話題が変わった場合は、最も時間・分量を割いた話題を採用する。複数が同等なら「AとB」の形でまとめる。
- 日付や連番は入れない（一覧側で管理されるため）。
- 社名・個人名・パスワード・APIキーなどの機密と思われる情報は名前に含めない。固有名詞が必要なら案件名や略称に置き換える。
- 記号は「・」「／」程度にとどめ、絵文字や括弧の多用は避ける。改行は使わない（`/rename` の行が2行に分かれる）。

## 出力形式

次の形式で簡潔に返す。前置きや会話の要約は書かない。

```
コピー済み：/rename <名前>
理由：<一文>

候補：
1. <候補A>
2. <候補B>
3. <候補C>
```

会話がまだ短く内容が特定できない場合も推奨名をコピーし、`コピー済み：/rename <名前>` の行と「内容が固まったら再提案できます」の一言だけを返す。
