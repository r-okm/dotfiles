# セッション名の提案

この会話（セッション）のここまでの内容をもとに、セッション一覧で後から見分けやすい名前を提案する。ツールは使わない。会話履歴とシステムプロンプトだけを材料にする。

このスキルは名前を提案するだけで、セッション名を書き換えることはしない（そのためのツールがない）。代わりに、ユーザーがそのままコピペできる1行を、推奨名を使ってコードブロックで必ず出力する。

## コピペ用の行

コピペ用の行は、ユーザーが `/rename` コマンドを実行できる環境かどうかで変える。

- 実行できる環境：`/rename <推奨名>`
- 実行できない環境：`<推奨名>` だけ。ユーザーはこれを各画面の名前変更欄に貼る。

論点は「ユーザーが入力欄から `/rename` を実行できるか」であり、自分（モデル）が実行できるかではない。`/rename` は Claude Code の組み込みコマンドで、モデルからは呼び出せず、利用可能なスキルやコマンドの一覧にも載らない。一覧に無いことや、自分で実行できないことを理由に「使えない」と判定しない。

判定は、システムプロンプトのうち、いま自分がどの画面・製品として動いているかを述べた記述で行う。

- 自分を Claude Code（Anthropic の CLI）と名乗る記述があれば、実行できる環境とみなす。
- Cowork や claude.ai のチャット、Claude のアプリとして動いている旨の記述があれば、実行できない環境とみなす。
- どちらとも読み取れない場合は、実行できない環境として扱う。

「Claude Code」という語があるだけでは、実行できる根拠にならない。別の製品の基盤として Claude Code に触れる記述や、Claude Code の製品紹介文は、自分の名乗りではない。

## 手順

1. 会話全体を振り返り、次の3点を把握する。
   - 主目的：ユーザーが最終的に何を得ようとしていたか（最初の依頼ではなく、会話の中心になった作業）
   - 対象物：扱ったファイル名、システム名、顧客名、機能名などの固有の手がかり
   - 成果・状態：完了したのか、途中なのか、調査だけなのか
2. 主目的＋対象物を軸に、切り口の異なる候補を3つ作る。
   - 候補A：成果物・作業内容を表す（例：「請求書PDFの一括分割スクリプト」）
   - 候補B：対象システム・案件名を前に出す（例：「KSC勤怠システム API調査」）
   - 候補C：課題・目的を表す（例：「月次バッチ遅延の原因調査」）
3. 3つのうち、一覧で最も見分けやすいものを推奨として1つ選び、理由を一文で添える。
4. 推奨名を「コピペ用の行」の形にしてコードブロックで出す。コードブロックの中はその1行だけにし、補足や引用符を入れない（コピペしてそのまま使える形にする）。

## 命名ルール

- 日本語で20字以内。超える場合は修飾語を削る。
- 「〜について」「〜の相談」「〜の件」などの中身のない語尾は使わない。
- 「雑談」「質問」「作業」のような一般語だけの名前にしない。固有名詞か具体的な動作を必ず含める。
- 会話の途中で話題が変わった場合は、最も時間・分量を割いた話題を採用する。複数が同等なら「AとB」の形でまとめる。
- 日付や連番は入れない（一覧側で管理されるため）。
- 社名・個人名・パスワード・APIキーなどの機密と思われる情報は名前に含めない。固有名詞が必要なら案件名や略称に置き換える。
- 記号は「・」「／」程度にとどめ、絵文字や括弧の多用は避ける。コマンドの引数として壊れないよう、バッククォートや改行は使わない。

## 出力形式

次の形式で簡潔に返す。前置きや会話の要約は書かない。コードブロックの中は「コピペ用の行」に従う（以下は `/rename` を実行できる環境の例）。

````
推奨：<名前>
理由：<一文>

```
/rename <名前>
```

候補：
1. <候補A>
2. <候補B>
3. <候補C>
````

会話がまだ短く内容が特定できない場合は、推奨とコピペ用の行だけを示し、「内容が固まったら再提案できます」と一言添える。
