# video-frames - 動画をフレーム画像にして読む

Read tool は画像（PNG/JPEG）と PDF しか読めず、動画コンテナ（MOV/mp4/webm…）は
読めない。そこで **動画 → 静止画フレーム → Read** という経路で中身を確認する。

抽出は `~/.claude/r-okm/scripts/video-frames.sh` が担当する（`ffmpeg` / `ffprobe`
に依存）。

**引数:** `$ARGUMENTS` の先頭は動画ファイルのパス。残りはそのままスクリプトに渡す。

## Step 1: まずメタデータを見る

長さと解像度が分からないと抽出間隔を決められない。

```bash
~/.claude/r-okm/scripts/video-frames.sh --info <video>
```

表示される fps は**実効値**（総フレーム数 ÷ 長さ）。コンテナの公称値とは一致しない
ことがあり、120fps を名乗るファイルの中身が 30fps ということもある。抽出間隔は
必ずこの実効値を基準にする。

## Step 2: 抽出モードを選ぶ

| モード | 用途 | 例 |
| --- | --- | --- |
| `uniform`（既定） | 全体の流れを掴む。まずこれ | `-m uniform -n 24` |
| `scene` | 画面が切り替わった瞬間だけ拾う | `-m scene -t 0.3` |
| `all` | 1 フレームも落とさず精査する。必ず `--start`/`--end` で区間を絞る | `-m all -s 1.0 -e 1.8 -n 0` |

画面録画の不具合調査は **「uniform で粗く全体 → 怪しい区間を `all` で 1 フレーム
単位」** の 2 段構えが効く。「一瞬だけ別画面が出る」類の症状は uniform では
取りこぼす（30fps なら 1 フレーム = 33ms しか映らない）。

主なオプション:

```text
-n, --max <n>              最大フレーム数（既定 24、0 で無制限）
-i, --interval <sec>       uniform: 何秒ごとに 1 枚か
-f, --fps <n>              uniform: 秒間何枚か
-t, --threshold <0..1>     scene: シーン変化スコアのしきい値（既定 0.3）
-s, --start / -e, --end    区間指定（秒 or HH:MM:SS）
-w, --width <px>           フレーム幅（既定 960、アスペクト比維持）
    --crop <W:H:X:Y>       先に指定領域だけ切り出す（元動画のピクセル座標）
-c, --contact-sheet [CxR]  タイル画像も出力（既定グリッド 3x3）
-o, --out <dir>            出力先
    --jpeg                 JPEG で出力（既定 PNG）
```

## Step 3: コンタクトシートで読む

**個別フレームを何枚も Read せず、`--contact-sheet` でまとめて 1 枚にする。**
各タイルには `#連番 t=秒` のラベルが焼き込まれるので、後から「t=1.13s の画面」と
特定できる。

```bash
~/.claude/r-okm/scripts/video-frames.sh -m uniform -n 24 -c 4x3 <video>
```

出力されたシートのパスを Read tool に渡す。

**画面の一部だけを詳しく見たいときは `--crop` を使う。** 個別フレームを何枚も Read
するより安く、注目領域がタイルいっぱいに拡大される。ラベルと `frames.tsv` の対応は
そのまま保たれるので、**生の ffmpeg でシートを組み直さないこと**（時刻の対応表を
失う）。

```bash
… --crop 340:230:190:290 -m all -s 2.1 -e 2.8 -n 0 -c 4x5 <video>
```

`--crop` で足りない細部（1 枚を最大解像度で見たい等）に限り、`frames.tsv` から
個別フレームのパスを引いて Read する。

### 枚数とコンテキストの目安

画像のトークン数はおよそ `幅 × 高さ ÷ 750`。長辺 1568px を超える画像は縮小される
ため、シートは縦横とも 1536px に収まるよう各タイルがグリッドのセルに内接する形で
自動計算される（縦長素材でも上限を超えない）。

| 読み方 | 概算コスト |
| --- | --- |
| 960x540 の個別フレーム 1 枚 | 約 700 tokens |
| コンタクトシート 1 枚（9〜35 フレーム） | 約 1,800 tokens |

**縦長の動画（スマホの画面録画など）は個別フレームが高くつく。** 既定の `-w 960`
だと 9:16 で 960x1706 ≒ 2,200 tokens とシート 1 枚より重い。個別フレームを読むなら
`-w 540` 程度まで落とすか、シートで済ませる。

- **1 回の確認でシートは 4 枚（≒ 36〜48 フレーム）まで、個別フレームは 8 枚まで**
  を目安にする。それ以上必要なら区間を絞り直す。
- グリッドは 3x3〜5x7 が実用範囲。タイルを細かくしすぎると画面内の文字が読めない。
  GUI の文字を読む必要があるなら 4x3 程度に留める。ただし 4x3 でも 1280px 幅の
  素材なら 3 割まで縮む。**文字の読み取りが結論に効くなら `--crop` で拡大する。**
- 長い動画（数分以上）は最初から全体を舐めない。`-n 24` で概観 → 区間を絞る。

## 出力先

既定は `<git_root>/.ignore/ai/video-frames/<動画名>/`（`.ignore` はグローバルに
gitignore 済み）。git リポジトリ外では `~/.cache/claude/video-frames/<動画名>/`。
`/tmp` は使わない。区間ごとに調べるときは `-o` で
`.ignore/ai/video-frames/<動画名>_detail` のように分けると上書きを避けられる。

生成物:

- `frame_0001.png …` — 抽出フレーム（`--jpeg` なら `.jpg`）
- `frames.tsv` — 1 行目が `# source: <元動画>`、以降が `index / time_sec / path` の
  対応表。**別の動画の出力を掴んでいないかはこの 1 行目で確かめる**（同名の動画は
  同じ出力先になる）
- `sheet_01.png …` — コンタクトシート（`-c` 指定時）

同じ出力先に再実行すると前回のフレームは削除される（連番が混ざるのを防ぐため）。
削除されるのは**新しい抽出が成功した後**なので、途中で失敗しても前回の結果は残る。
ただし**同じ出力先への同時実行は保護されない**（差し替えは複数手順で、不可分では
ない）。並行して調べるときは `-o` を分けること。
パスは `-o` に相対パスを渡しても絶対パスで出力されるので、そのまま Read tool に
渡せる。

`--max` の上限に当たって動画の末尾まで届かなかった場合は `warning: capped at …` が
出る。**この警告が出たフレーム表は動画全体ではない。** 区間を絞るか `-n` を上げる。

## 注意点

- **`scene` のしきい値は素材で変わる。** デジタルな画面録画なら既定の 0.3 で切り
  替わりを拾えるが、**スマホで画面を撮った動画**は手ブレ・映り込み・パネル外の
  背景が混じるため画面全体の変化率が小さく、0.3 ではほぼ検出されない。
  `-t 0.02`〜`0.05` まで下げる。逆に下げすぎると手ブレを拾って `--max` に張り付く。
- **2 画面が重なったフレームは遷移の目印。** クロスフェードでも実写撮影の露光跨ぎ
  でも起きるので、**どちらの機序かは断定しない**。重なりフレームは「どちらの画面か」
  を決められず、**どちらの表示時間にも数えない**。言えるのは直前に遷移が発火した
  ことだけで、「その画面が出ていた」根拠は単独で写っているフレームに限る。
- **フレーム時刻から言えるのは画面側の出来事まで。** 「いつ遷移したか」「何 ms 間隔
  で連続したか」は読めるが、**それを起こした操作**（単発タップか連打か、押しっぱなし
  か）は撮影解像度では判別できないことが多い。操作を断定せず、観測できた遷移の時刻
  だけを根拠にする。
- 音声は無視される（映像のみ）。音が判断に必要な内容は扱えない。
- OCR はしていない。画面の文字はフレームを Read して読み取る。
