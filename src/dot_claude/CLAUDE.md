# 会話

- 返答は常に日本語で書く。
- ファイルを編集するときは、そのファイル(またはリポジトリ内の同種のファイル)で使われている言語に合わせる。コミットメッセージはリポジトリの履歴の言語に合わせる。前例がなければ、ファイルは日本語、コミットメッセージは英語で書く。

# 日本語の文書

- 記事、ドキュメント、PR の説明文、コミットメッセージなどの日本語の文章を書いたり直したりするときは、常に yomiyasu:yomiyasu スキルで推敲する。コードを直したあとの作業の報告には使わなくてよい。

# プロジェクト構成

- `<project_root>/.ignore` ディレクトリはグローバルに gitignore されている。セッション後も残す価値のあるファイル(調査メモ、結果、生成物、中間作業ファイル)を AI が作るときは、`~/.claude/r-okm/scripts/claude-ai-dir.sh` が出力するセッションごとのディレクトリに置く。スクリプトが失敗したらハーネスのスクラッチパッドを使う。ディレクトリは最初に書き込むときまで作らない。
- worktree スキル(`git-worktree-herdr`)で作った worktree の `.ignore` は、元リポジトリの `.ignore` へのシンボリックリンクになっている。worktree を削除しても消えるのはリンクだけで、中のファイルは元リポジトリ側に残る。worktree を削除する前に `.ignore` の中身の退避を提案しなくてよい。
- 設定やスクリプトで決まっているパス(スキルの既定の出力先など)は、その場所のままにする。
- セッション内で使い捨てるファイルはハーネスのスクラッチパッドでよい。
- サブエージェントにそうしたファイルを書かせるときは、ディレクトリの絶対パスを指示文に入れる。

# gitignore されたプロジェクト別設定

- `CLAUDE.local.md` などの gitignore されたプロジェクト別設定ファイルは、project-ignores リポジトリ(`~/src/github.com/r-okm/project-ignores`)へのシンボリックリンクのことがある。編集するときはリンクを解決し(`readlink -f`)、そのリポジトリにある実体を編集する。

# WSL

- URL や HTML ファイルをユーザーのブラウザで開くときは `xdg-open` を使う。`~/.local/bin/xdg-open` が Windows 側の既定のアプリに渡すので、`explorer.exe` や `wslview` は使わない。
